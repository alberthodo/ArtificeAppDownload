What we measured, including where Artifice didn't help.

The Artifice teamLetter 1 · about 6 minutes to read

New here? Once a month, the people who make Artifice write about what we shipped and what we learned. One email, no promotions. This is the first one.

This month we spent more time measuring Artifice than building it. The first answer we got was no.

Artifice reads your project on your computer and hands your AI tools the parts they need. The claim behind it is simple: an AI that's handed the right passages should spend less finding them. We wanted to know if that's true, measured as carefully as we could, before we said it anywhere.

How we tested

We ran Claude Code with Claude Sonnet 5.5, the same pinned build in every run, with no shell and no web access, once with Artifice and once without. Cost is what Claude Code itself reports at Anthropic's list prices. Every comparison is paired: the same task, the same run number.

For bug fixes we used 50 real GitHub issues from SWE-rebench's March 2026 set, three runs each, and every patch was scored by the benchmark's own test harness. We dropped a better-known set first. On SWE-bench Verified Mini, the model named the files to change for 94% of the tasks from the issue text alone: it had largely memorized them.

What we found

On bug fixes, Artifice saved nothing

Our first versions handed Claude a pack of the code most relevant to each request. They cost 9–11% more per task, and solved no more of them. So we tried the best pack anyone could give: the exact lines the real fix changes. It still cost the same.

Claude Code is already good at this. It finds where to make a fix in about eight tool calls on its own. What it spends turns on is understanding the code around that place, and it reads that whatever it's given. On a request to change code, every token a context tool adds is extra cost.

So Artifice now stays out of the way 0.1.6

Artifice now tells a question ("how does this work?") from a change ("fix this") on your computer, in about 30 milliseconds, without asking any AI. For a change, or when it's unsure, it adds nothing. It labelled all 720 benchmark questions and all 145 issue reports correctly, and was right 92.5% of the time on 120 prompts written the way people type. Most of its mistakes were questions taken for changes, which cost nothing: they just get no help.

With that, and with Artifice's own tools no longer loaded into every conversation, the 150 bug-fix runs came out even:

The 95% confidence interval on the cost runs from −3.5% to +3.2%: no saving, and no extra cost.

On questions, small packs of real code helped

Questions about how code works take broad reading, and that is what a pack can replace. Two things mattered. The pack has to hold the code itself, not one-line summaries of it, or Claude reads the files anyway. And it has to be small: a 2,500-token pack saved 6% on our design questions, 1,200 saved 10%, and 700 saved 14%. At 400 it was too thin to answer from.

Then the humbling part. On 60 questions we had never used for anything, the 700-token setup saved 3.8%, with 10% fewer turns and the same answer quality, 80.4 out of 100 both ways. The 14% from our 30 design questions didn't hold. Small design sets overstate, and we nearly believed ours.

Then we rebuilt search on meaning 0.1.7

Trying 0.1.6 on our own projects gave odd answers. “Tell me about this project” got a research note, a Unity physics settings file and part of an instructions file, all matched on the word “project”. So we rebuilt how Artifice finds things: by what a question means, with a small model that runs on your computer.

We tested it on five real projects, with 144 questions held back from every choice we made:

Two benchmarks, two numbers, and we want to be straight about why they differ. The 3.8% is on popular open-source Python projects the model may partly know already, which shrinks any benefit. The 28% is on our own question set: written by one Claude session and checked by another, not by users, and graded by an AI. That became 0.1.7, released November 1.

What broke, or was hard

  • Folders with spaces in their names confused Claude. The first 0.1.7 run scored lower on knowledge questions. In the worst case, Claude read Artifice docs/concepts/… as the word “Artifice” and a path, failed to open the file and gave up. 0.1.6 had the same flaw. Paths with spaces are now quoted.Fixed in 0.1.7
  • “Database is locked”. After a big change to a project, like switching git branches, several AI tools asking at once could fail or wait minutes. Requests no longer wait behind each other.Fixed in 0.1.6, shipped in 0.1.7
  • Composer Pro is paused. The optional summaries model is paused while we build a better version. Projects that used it switch to Composer and keep the summaries it already wrote.Paused
  • What we haven't measured. One agent and one model so far, single tasks rather than long sessions, and answers graded by an AI. Other agents work differently and may save more on changes.Still true

What's next

Your folders hold more than code. Artifice 0.1.7 still skips PDF, Word, Excel and PowerPoint files, and that's next. After that, other AI tools than Claude Code, measured the same way. No dates we can't keep.

One question for you

What do you mostly ask your AI to do: answer questions about your work, or change it?

One line is plenty, and which AI tool you use. It tells us where Artifice should help next.
