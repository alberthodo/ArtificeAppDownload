Connecting AI tools

Connect each AI tool once, and it can use every project you add. Artifice adds itself to the tool's own settings on your computer, never to your projects' files.

Three ways in#

Artifice reaches your AI tools in three ways. Connecting a tool sets up the first two for you.

  1. The MCP serverYour AI calls Artifice's tools, such as artifice_context, through artifice mcp. See MCP tools.
  2. Hooks, in Claude CodeArtifice adds a briefing to every prompt and watches which files Claude Code opens. This works even when the AI never calls an MCP tool, which independent tests found is common. See Claude Code hooks.
  3. The command lineAny AI tool that can run shell commands can use artifice ask "<task>", artifice expand <id> and artifice remember "…".

Connect a tool#

In the app, open AI tools in the sidebar. Each tool installed on your computer has a Connect button. From a terminal, use artifice connect:

# see what's connected, and how
$ artifice connect

# connect a tool: claude-code, claude-desktop, codex, gemini,
# antigravity, cursor, windsurf or vscode
$ artifice connect claude-code

# disconnect it again
$ artifice connect codex --remove

Then restart the tool, or start a new session, so it picks Artifice up:

ToolAfter connecting
Claude (the app)Quit and reopen the Claude app
Claude CodeStart a new Claude Code session
CodexStart a new Codex session
Gemini CLIStart a new Gemini CLI session
AntigravityRestart Antigravity
CursorRestart Cursor
WindsurfRestart Windsurf (now Devin Desktop)
VS CodeRestart VS Code, and use Copilot in agent mode

In Claude Code, you'll see it at once. The artifice MCP server is listed, each prompt gets an <artifice-context> block, and the first session also gets an <artifice-digest>, a short overview of the project.

The server and hooks work out the project from the folder your AI is working in. A project you've added gets a briefing; any other folder gets nothing.

What Connect changes#

Connect adds Artifice to the tool's user-wide settings, so it works in every project without touching any of them.

  • Every settings file is backed up first, to backups/ in Artifice's data folder.
  • Disconnect removes only Artifice's entries, under any name, from the tool's user settings and from the per-project entries in your own user files.
  • A project's shared files are left alone, such as a committed .mcp.json. Artifice lists them instead, so you can decide.
  • Nothing is added twice. If Artifice is already in a tool's user settings under another name, for example from claude mcp add --scope user Artifice …, Connect adds only the Claude Code hooks.

Connected however you set it up#

The app and artifice connect show a tool as connected however Artifice got into its settings: from the app, from the tool's own command (claude mcp add, codex mcp add, gemini mcp add), from the command line, or by hand. The server can have any name. Artifice reads every file the tool reads, and recognises its own server by the program it starts: an artifice… program with the mcp argument, directly or through a shell (sh -c "… artifice mcp"), or any server named artifice.

A tool set up for only some projects shows Connected · in shop, for example, and Details lists the files.

Seen in use. The MCP server and the hooks also note each AI tool that actually talks to Artifice. A tool that isn't in any settings file Artifice knows, but has used it in the last 30 days, shows as In use · set up outside Artifice: a team-managed setup, a plugin or a wrapper script, for example. It has no Disconnect button, because there's nothing for Artifice to remove. MCP apps Artifice doesn't recognise, such as Zed, Cline, opencode or Kiro, are listed under Other apps using Artifice.

Settings files with comments, or written on Windows#

Gemini CLI's settings.json and other tools' files may hold comments (//, /* */) and trailing commas, and Windows editors often save a byte-order mark at the start. Artifice reads all of these. When a file has comments, Artifice adds its entry as text and keeps your comments and layout.

A file that still can't be read is never changed. AI tools shows a settings file can't be read, with the file and the line, and artifice connect lists it under the tool. Fix that line in a text editor and connect again.

On Windows, Artifice writes its program path as C:\…, never the \\?\C:\… form some tools can't start.

Any other MCP app#

Any app that supports MCP servers can use Artifice. Open AI tools › Details in the app to copy a server definition, or print one:

# prints a server definition for any MCP app
$ artifice connect generic
{
  "artifice": {
    "command": "/abs/path/to/artifice",
    "args": ["mcp"]
  }
}

By default the server uses the folder the app starts it in, the app's MCP roots, or, for Claude Code, CLAUDE_PROJECT_DIR. To pin one project, add "--project", "/path/to/project" to the args, or set ARTIFICE_PROJECT. Chat apps with no folder can pass project to artifice_context.

The MCP client's label is kept as mcp:<name>, with the host in brackets when Claude Code reports one, for example mcp:claude-code (claude-vscode). Only CLAUDE_CODE_ENTRYPOINT is read from the environment. Anything else the tool passes on, such as account IDs and email addresses, is never read or stored.

Each request is counted once#

  • The same hook set up twice, for example user-wide and in an older per-folder .claude/settings.local.json, or by two copies of Artifice. Each event is claimed once across processes: a file read by its tool_use_id, a prompt by session and text within 10 seconds, and a session start by session within 10 seconds. Only the first copy delivers and counts.
  • Several tools, projects and processes at once. Each request is written to its project and copied to the savings ledger under a key that can't repeat. Copying again from any process adds nothing, and a row that couldn't be copied is picked up the next time any process opens the project.

Older per-folder setup#

Before Artifice connected tools for the whole computer, artifice connect <tool> --write wrote .mcp.json, .claude/settings.local.json, .cursor/mcp.json and a section in CLAUDE.md or AGENTS.md into each folder. That style is still there as artifice connect <tool> --here --write.

AI tools lists any such files it finds under Old setup files, and can remove Artifice's entries from them.

Check that it works#

  • In the app, AI tools shows when each tool last used Artifice ("Used 2 minutes ago"), and Activity lists every briefing as your AI works.
  • artifice connect shows each tool's state, where it's set up, and other MCP apps that have used Artifice.
  • artifice savings shows requests going up as your AI works. Totals cover every project.
  • artifice doctor prints a report of versions, folders, projects and each tool's connection. It holds no file contents or questions, so it's safe to paste into an email to us.
